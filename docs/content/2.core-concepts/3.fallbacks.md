---
title: Fallbacks
description: What happens when nothing resolves — including the one that can bite you.
---

Nothing is configured out of the box, so every role has to degrade gracefully rather than throw. The same fallbacks apply whether a row is missing from the table or its patterns simply found nothing.

| Role | Found | Not configured, or not found |
|---|---|---|
| `resource` | Use it | Wrap in a plain `JsonResource` |
| `collection` | Use it | `{Resource}::collection()` |
| `request` | Validate with it | **No validation** — see below |
| policy | Enforce the ability | Skip silently |

## Policies: present means enforced, absent means skipped

```php
class PostPolicy
{
    public function update(mixed $user, Post $post): bool { /* … */ }
    // no viewAny, no delete
}
```

`update` is enforced. `index` and `destroy` are not authorized at all — not denied, *skipped*. This is deliberate: it lets you add abilities one at a time without every unlisted action returning 403.

If you would rather a missing policy be an error:

```php [config/easy-crud.php]
'authorization' => 'strict',   // optional (default) | strict | none
```

## Validation: the one that can bite you

::warning
When no request class resolves **and** the controller declares no `rules()`, the action runs with **no validation at all**. The raw request input is passed to the model, and your `$fillable` / `$guarded` is the only thing filtering it.
::

It is what lets a controller work before you have written a request class. It is also how you ship a mass-assignment bug.

Three ways to know, and to stop it:

::steps{level="3"}
### Ask the package

```bash
php artisan easy-crud:conventions Post
```

```ansi
  Request
      store    App\Http\Requests\StorePostRequest      not found → no validation ✗
```

### Declare inline rules

No class needed:

```php
protected function rules(string $action): array
{
    return match ($action) {
        'store' => ['title' => 'required|string|max:255'],
        'update' => ['title' => 'sometimes|string|max:255'],
        default => [],
    };
}
```

### Refuse to run unvalidated

```php [config/easy-crud.php]
'strict_requests' => true,
```

Now `store` and `update` throw a `CrudConfigurationException` naming the classes it looked for, instead of silently writing whatever arrived. Read actions are unaffected.
::

::tip
Turn `strict_requests` on once your write endpoints all have request classes or `rules()`. From then on, forgetting one is an error at the point you forget it, rather than a silent hole.
::
