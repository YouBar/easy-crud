---
title: Precedence & overriding
description: One ladder, used for every role. Property, method, config, fallback.
---

Everything `easy-crud` resolves follows the same four-rung ladder. There is no per-role special casing to memorise.

```
1. property        protected ?string $resource = PostResource::class;
        ↓ else
2. method          protected function resource(): string { … }
        ↓ else
3. config pattern  first class_exists() hit in the conventions table
        ↓ else
4. fallback        generic JsonResource · no validation · Eloquent · skip policy
```

Higher rungs win. A rung that is not used falls through silently to the next.

## Rung 1 — a property

The shortest way to override a single class:

```php
class PaymentController extends CrudController
{
    protected string $model = Payment::class;

    protected ?string $resource = PaymentResource::class;
}
```

Use this when the answer is a constant.

## Rung 2 — a method

Use this when the answer depends on something — the request, the user, the model:

```php
protected function resource(): string
{
    return request()->user()?->isAdmin()
        ? AdminPostResource::class
        : PostResource::class;
}
```

## Rung 3 — the conventions table

Project-wide defaults. See [the conventions table](/core-concepts/conventions).

## Rung 4 — fallbacks

What happens when nothing matched at all. See [fallbacks](/core-concepts/fallbacks).

## Worked example: one controller, a different resource

Say your project resolves resources by pattern:

```php [config/easy-crud.php]
'conventions' => [
    'resource' => ['App\Http\Resources\{Model}Resource'],
],
```

Every controller now finds its own `{Model}Resource`. Three ways for one
controller to do something else, each at a different rung:

### A different class

```php
class PaymentController extends CrudController
{
    protected string $model = Payment::class;

    protected ?string $resource = Billing\PaymentPresenter::class;
}
```

The project default stays in place for every other controller.

### A class chosen at runtime

```php
protected function resource(): string
{
    return request()->user()?->isAdmin()
        ? AdminPostResource::class
        : PostResource::class;
}
```

### Nothing at all

```php
protected ?string $resource = null;   // falls through to the conventions table
```

::caution
`null` means *"fall through"*, not *"disabled"*. It is the value every role
starts at, so setting it explicitly changes nothing. To stop a role resolving,
remove its row from the conventions table or override the method that uses it.
::

## When nothing matches

A row whose patterns find no class is not an error. Resolution returns nothing
and the [fallback](/core-concepts/fallbacks) takes over — a plain
`JsonResource`, no validation, no policy check. Run
`php artisan easy-crud:conventions {Model}` to see which rung answered.
