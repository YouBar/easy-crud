---
title: Overriding a method
description: Every extension point, its signature, its default, and when to reach for it.
---

This is the primary way to customise `easy-crud`. Every method below is `protected`, has a working default, and can be overridden independently — the ones you leave alone keep behaving.

::tip
In PhpStorm, `Ctrl+O` inside a `CrudController` lists all of them with signatures.
::

## The full table

| Method | Default |
|---|---|
| `scope(Builder $q): Builder` | Passthrough |
| `filter(Builder $q): mixed` | Passthrough |
| `with(string $action): array` | `[]` |
| `prepare(mixed $data, string $action): mixed` | Passthrough |
| `paginate(Builder $q): mixed` | Configured strategy |
| `perPage(): int` | Config, clamped to `max` |
| `find(mixed $key): Model` | `resolveRouteBinding`, 404 on miss |
| `create(array $data): Model` | `Model::create()` |
| `applyUpdate(Model $m, array $data): Model` | `$m->update()` |
| `delete(Model $m, array $data = []): void` | `$m->delete()` |
| `rules(string $action): array` | `[]` |
| `validated(Request $r, CrudAction $a): array` | Request class → rules → passthrough |
| `authorizeAction(CrudAction $a, ?Model $m): void` | Policy if present, else skip |
| `transform(mixed $data): JsonResource` | Resource / collection class |
| `respond(JsonResource $r, CrudAction $a): JsonResponse` | Configured status code |

## Querying

`scope()` and `filter()` split the index query in two, and the names say which runs first.

```php
// What may this user see at all? Authorization-shaped.
protected function scope(Builder $query): Builder
{
    return $query->where('organization_id', organization()->id);
}

// What did they ask for? User-driven.
protected function filter(Builder $query): Builder
{
    return QueryBuilder::for($query)
        ->allowedFilters(['name'])
        ->allowedSorts(['id', 'name']);
}
```

Keeping them separate means a filter can never widen a scope.

## Eager loading

`with()` is declarative and per-action:

```php
protected function with(string $action): array
{
    return match ($action) {
        'show' => ['author', 'comments.author'],
        'index' => ['author'],
        default => [],
    };
}
```

`index` applies them to the query; the other actions apply them to the model.

## Shaping a result

`prepare()` runs after the record is fetched and before it is transformed. It is the escape hatch for everything `with()` cannot express — `loadCount()` with closures, `loadMorph()`, appends, computed attributes:

```php
protected function prepare(mixed $data, string $action): mixed
{
    if ($data instanceof Model && $action === 'show') {
        $data->loadCount([
            'lessons as attended_count' => fn ($q) => $q->where('present', true),
            'lessons as missed_count' => fn ($q) => $q->where('present', false),
        ]);
    }

    return $data;
}
```

It receives a `Model` for show, store and update, and a paginator or collection for index.

::note
`prepare()` exists so that these cases do **not** require overriding an action method. If you find yourself overriding `show()` just to shape the model, use this instead.
::

## Persistence

```php
protected function create(array $data): Model
{
    return app(CreatePost::class)->handle($data);
}

protected function applyUpdate(Model $model, array $data): Model
{
    $model->update($data);
    $model->tags()->sync($data['tags'] ?? []);

    return $model;
}

protected function delete(Model $model, array $data = []): void
{
    // $data is whatever the destroy action validated.
    app(PostService::class)->archive($model, $data['reason'] ?? null);
}
```

`delete()` receives the validated data, so a `DestroyPostRequest` can carry cascade flags or a reason.

## Pagination

```php
protected function perPage(): int
{
    return 50;
}
```

Or project-wide, including the strategy:

```php [config/easy-crud.php]
'pagination' => [
    'strategy' => 'cursor',            // length_aware | simple | cursor | none
    'default' => 15,
    'max' => 100,
    'query_keys' => ['perPage', 'per_page'],
],
```

## When overriding is not enough

Override the action itself. You keep the other four:

```php
public function destroy(Request $request, mixed $key): JsonResponse
{
    // entirely yours
}
```

This is supported, and occasionally the right call. Before reaching for it, check whether `prepare()`, `delete($model, $data)` or `scope()` already covers what you need — most cases that look like they need a custom action do not.
