---
title: Custom roles
description: Add your own row to the conventions table — and know exactly what that does.
---

::caution
A row you add is **resolved only**. The package has behaviour for three roles —
`resource`, `collection` and `request` — and no others, so a role name means
nothing on its own until you read it.
::

## Adding one

```php [config/easy-crud.php]
'conventions' => [
    'repository' => ['App\Repositories\{Model}Repository'],
],
```

Nothing happens yet.

## Consuming it

```php
abstract class BaseCrudController extends CrudController
{
    protected function create(array $data): Model
    {
        return $this->resolved('repository')->store($data);
    }

    protected function applyUpdate(Model $model, array $data): Model
    {
        return $this->resolved('repository')->save($model, $data);
    }
}
```

Every controller extending `BaseCrudController` now resolves *its own* model's repository, by pattern. You wrote the behaviour once; the row supplies the per-model lookup.

## `resolved()`

```php
protected function resolved(string $role, ?string $action = null): ?object
```

Returns the container-resolved instance, or `null` when the role is disabled or nothing matched. Use `classFor()` if you want the class-string instead of an instance.

## Is this worth it?

Compared with `app(PostRepository::class)` written out in each controller, a custom role buys you two things:

1. One override in a base class covers every model.
2. The row appears in `easy-crud:conventions`, so the X-ray stays complete.

It is a naming-convention helper, not magic. With three controllers, writing the
class name out is probably clearer. For a worked example across a whole
application, see [applying your own patterns](/customisation/design-patterns).

## Action-per-class layouts

The same trick covers one-class-per-action projects, since `request` and any custom role are resolved per action:

```php
'conventions' => [
    'action' => ['App\Actions\{Action}{Model}'],   // App\Actions\StorePost
],
```

```php
protected function create(array $data): Model
{
    return $this->resolved('action', 'store')->handle($data);
}
```
