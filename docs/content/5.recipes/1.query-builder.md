description: Filtering, sorting and includes in one override.
---

`easy-crud` has no opinion about filtering. `filter()` is where it goes.

```php
use Spatie\QueryBuilder\QueryBuilder;
use Spatie\QueryBuilder\AllowedFilter;

class PostController extends CrudController
{
    protected string $model = Post::class;

    protected function scope(Builder $query): Builder
    {
        return $query->where('organization_id', organization()->id);
    }

    protected function filter(Builder $query): Builder
    {
        return QueryBuilder::for($query)
            ->allowedFilters([
                'title',
                AllowedFilter::exact('status'),
            ])
            ->allowedSorts(['id', 'title', 'created_at'])
            ->allowedIncludes(['author', 'comments'])
            ->defaultSort('-created_at')
            ->getEloquentBuilder();
    }
}
```

::note
`scope()` runs before `filter()`, and `QueryBuilder::for()` accepts the already-scoped builder. A user-supplied filter can therefore never widen the tenant scope.
::

## Project-wide

If every controller does this, put it in your own base class and let each controller declare only what it allows:

```php
abstract class BaseCrudController extends CrudController
{
    protected function filter(Builder $query): Builder
    {
        return QueryBuilder::for($query)
            ->allowedFilters($this->filters())
            ->allowedSorts($this->sorts())
            ->getEloquentBuilder();
    }

    protected function filters(): array { return []; }
    protected function sorts(): array { return []; }
}
```
