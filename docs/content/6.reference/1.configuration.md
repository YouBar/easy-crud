## `conventions`

Ships empty. Nothing is resolved until you add rows. Covered in full on
[the conventions table](/core-concepts/conventions).

## `pagination`

```php
'pagination' => [
    'strategy' => 'length_aware',
    'default' => 15,
    'max' => 100,
    'query_keys' => ['perPage', 'per_page'],
],
```

| Key | Meaning |
|---|---|
| `strategy` | `length_aware` · `simple` · `cursor` · `none` |
| `default` | Used when the request names no page size |
| `max` | Hard ceiling — a request asking for 10 000 gets this |
| `query_keys` | Tried in order; the first one present wins |

## `strict_requests`

```php
'strict_requests' => false,
```

`false` (default) — a write action with no request class and no `rules()` runs unvalidated.

`true` — that situation throws a `CrudConfigurationException` naming every class it looked for. Read actions are unaffected. See [fallbacks](/core-concepts/fallbacks).

## `responses`

```php
'responses' => [
    'store' => 201,
    'update' => 200,
    'destroy' => 204,
    'destroy_returns_resource' => false,
],
```

Set `destroy_returns_resource` to `true` to return the deleted record instead of an empty body — useful for optimistic UIs that want the final state.

## `authorization`

```php
'authorization' => 'optional',
```

| Value | Behaviour |
|---|---|
| `optional` | Enforce an ability the policy defines; skip one it omits. The default, and what makes a policy-free controller work. |
| `strict` | A missing policy, or a policy missing the ability, is a configuration error. |
| `none` | Never authorize. For applications that gate entirely in middleware. |
